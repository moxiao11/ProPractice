<h3 id="wk-exec-overview">一、从代码到可执行文件的宏观视角</h3>

计算机其实非常“笨”，它的 CPU 只能理解由 `0` 和 `1` 组成的**机器语言（Machine Language）**。而我们平时写的 C、C++ 代码被称为**高级语言（High-level Language）**，是给人看的。

为了让计算机执行我们写的代码，需要一个翻译系统（编译系统），把高级语言一步步“翻译”成机器语言。这个翻译过程通常分为四个阶段：**预处理（Preprocessing）**、**编译（Compilation）**、**汇编（Assembly）** 和 **链接（Linking）**。



---

<h3 id="wk-exec-steps">二、执行流程的四大步</h3>

我们以一段极其简单的 C 语言代码 `hello.c` 为例来看看它的演变：

```c
#include <stdio.h>

int main() {
    int a = 2;
    int b = 3;
    int sum = a + b;
    printf("Sum is: %d\n", sum);
    return 0;
}
```

#### 1. 预处理阶段 (Preprocessing)
* **做了什么**：主要处理源代码中以 `#` 开头的指令，比如 `#include` 和 `#define`。预处理器会把引用的头文件（如 `stdio.h`）的内容直接插入到你的代码文本中。
* **形态变化**：原本只有几行的 `hello.c`，经过预处理后会变成一个非常长的大型文本文件（通常后缀为 `.i`），但它**仍然是高级语言的纯文本**。

#### 2. 编译阶段 (Compilation)
* **做了什么**：编译器（Compiler）会对代码进行语法分析和优化，然后将高级语言翻译成**汇编语言（Assembly Language）**。不同的高级语言经过这一步，都可以变成同一种汇编语言。
* **形态变化**：从人类容易读懂的高级代码，变成了包含各种指令（如 `mov`, `add`）的汇编代码文本（通常后缀为 `.s`）。
* **形态举例**：
 对应的汇编代码片段大概长这样：
  ```assembly
  movl    $2, -4(%rbp)     //把 2 存起来 (int a = 2)
  movl    $3, -8(%rbp)     //把 3 存起来 (int b = 3)
  movl    -4(%rbp), %edx
  movl    -8(%rbp), %eax
  addl    %edx, %eax       //执行加法 (a + b)
  ```

#### 3. 汇编阶段 (Assembly)
* **做了什么**：汇编器（Assembler）将上一步的汇编语言文本，逐句翻译成计算机能看懂的机器指令（机器语言），并把它们打包成一种叫做可重定位目标程序（Relocatable Object Program）的格式。
* **形态变化**：从文本文件变成了完全由 `0` 和 `1` 组成的**二进制文件**（通常后缀为 `.o` 或 `.obj`）。这个时候人类已经无法用普通文本编辑器阅读它了。

#### 4. 链接阶段 (Linking)
* **做了什么**：我们的代码里调用了 `printf` 函数，但这个函数是我们自己写的吗？不是，它是 C 标准库提供好的。链接器（Linker）负责把我们刚刚生成的 `.o` 二进制文件，和标准库中预先编译好的 `printf.o` 文件“拼接”（链接）在一起。
* **最终形态**：生成最终的、可以被操作系统加载并运行的**可执行文件**（如 Windows 下的 `.exe` 或者 Linux 下的无后缀可执行文件）。

<h3 id="wk-exec-resources">三、推荐阅读与扩展资源</h3>

关于程序底层的执行逻辑，强烈推荐通过以下资源建立起对“计算机系统”的大致了解：

1. **推荐书目**：
   * **《深入理解计算机系统》（CSAPP - Computer Systems: A Programmer's Perspective）**：这本书的第 1 章极好地（且图文并茂地）解释了漫游计算机系统的整个过程。如果只看入门概念，读完第 1 章和第 7 章（链接）的开头就足够了。
2. **在线文档与社区**：
   * [GCC 官方文档](https://gcc.gnu.org/onlinedocs/)：了解编译器是如何通过命令（如 `gcc -E`, `gcc -S`）拆分上述步骤的。
