<h3 id="wk-algo-overview">一、什么是算法与时间复杂度？</h3>

**算法（Algorithm）** 就是解决特定问题的一系列明确的步骤或指令。就像菜谱一样，输入是食材，输出是菜肴。

**时间复杂度**用来衡量随着输入数据量（通常用 $n$ 表示）的增加，算法执行时间（或操作次数）的增长趋势。我们通常使用“大 O 符号”（Big O notation）来表示，比如 $O(1)$、$O(n)$ 等。



> **核心提示：** 时间复杂度衡量的不是具体的运行秒数（因为这取决于电脑配置），而是**操作次数的增长规模**。

<h3 id="wk-algo-complexity">二、常见的时间复杂度（从快到慢排布）</h3>

这里我们稍微深入一点，了解一下从最快的常数阶到极慢的指数阶，它们在实际工程中非常重要。

#### 1. $O(1)$ - 常数时间复杂度
无论输入的数据量 $n$ 有多大，算法执行的时间始终保持不变。

**代码示例（C++）：**
```cpp
#include <iostream>
#include <vector>

// 无论数组有多长，只取第一个元素，执行一次核心操作
void printFirst(const std::vector<int>& arr) {
    if (!arr.empty()) std::cout << arr[0] << std::endl; 
}
```

#### 2. $O(\log n)$ - 对数时间复杂度
非常高效。每次操作都能将剩余需要处理的数据量减半。最经典的例子是**二分查找**。

**代码示例（C++）：**
```cpp
// 在一个有序数组中查找目标值
int binarySearch(const std::vector<int>& arr, int target) {
    int left = 0, right = arr.size() - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] == target) return mid;      // 找到了
        if (arr[mid] < target) left = mid + 1;   // 砍掉左半边
        else right = mid - 1;                    // 砍掉右半边
    }
    return -1;
}
```
*解释：如果数组有 1024 个元素，最多只需要找 10 次（因为 $2^{10} = 1024$）。数据量即使达到 100 万，最多也只需约 20 次操作。*

#### 3. $O(n)$ - 线性时间复杂度
算法执行的时间与输入数据量 $n$ 成正比。

**代码示例（C++）：**
```cpp
// 寻找数组中的最大值，必须遍历整个数组
int findMax(const std::vector<int>& arr) {
    int max_val = arr[0];
    for (int i = 1; i < arr.size(); i++) {
        if (arr[i] > max_val) max_val = arr[i];
    }
    return max_val;
}
```

#### 4. $O(n \log n)$ - 线性对数时间复杂度
这是大多数高效排序算法（如**归并排序**、**快速排序**）的时间复杂度。可以理解为：执行了 $n$ 次，每次操作的复杂度是 $O(\log n)$。

**代码示例（C++）：**
```cpp
#include <algorithm>
#include <vector>

void sortArray(std::vector<int>& arr) {
    // C++ 标准库的 sort 通常的平均和最坏时间复杂度都被优化到了 O(n log n)
    std::sort(arr.begin(), arr.end());
}
```

#### 5. $O(n^2)$ - 平方时间复杂度
通常出现在简单的双层嵌套循环中（如冒泡排序）。数据量 $n$ 翻倍，时间会变成 4 倍。数据量很大时要尽量避免。

**代码示例（C++）：**
```cpp
// 打印所有可能的数对（双层循环）
void printPairs(const std::vector<int>& arr) {
    for (int i = 0; i < arr.size(); i++) {
        for (int j = 0; j < arr.size(); j++) {
            std::cout << arr[i] << ", " << arr[j] << std::endl;
        }
    }
}
```

#### 6. $O(k^n)$ - 指数时间复杂度（整数的 $n$ 次方）
当时间复杂度表现为一个整数的 $n$ 次方时，算法的耗时会随着数据量 $n$ 的增加呈**爆炸式增长**。这种情况通常出现在递归尝试所有可能性的算法中。除非数据量极小，否则在实际开发中是不可接受的。

**代码示例（C++）：**
```cpp
// 计算斐波那契数列的第 n 项（未经优化的简单递归）
// 每次计算都会分裂成两个子计算，形成一棵庞大的递归树
int fibonacci(int n) {
    if (n <= 1) return n;
    return fibonacci(n - 1) + fibonacci(n - 2);
}
```
*解释：计算第 10 项可能瞬间完成，但如果计算第 50 项，计算机可能需要跑上好几个小时。*

//求解以下程序的复杂度
int sub1(int m){
